## 1. 范围和定位

PanFind 近期只支持百度网盘和夸克网盘，不计划接入第三家网盘。两者分别验证两种有代表性的数据获取路径：

- 百度从官方客户端维护的完整本地数据库加载快照；
- 夸克通过只读远端全量扫描获取元数据，再由 PanFind 持久化完整快照。

夸克 Provider 的目标不是实时挂载网盘，而是为 AI Agent 提供一份有明确生成时间、可快速查询、内部完整一致的只读 POSIX 元数据快照。

## 2. 已验证的客户端行为

### 2.1 本地持久化组成

夸克 Windows 客户端具有上传、下载和备份任务数据库，但这些 SQLite 数据库只描述传输任务，不是完整文件树。

客户端还会在 IndexedDB 中保存访问过的目录及其文件列表。实际记录包含：

- 文件 ID 和父目录 ID；
- 文件名；
- 文件或目录类型；
- 文件大小；
- 创建和修改时间；
- 分类和缩略图等辅助信息。

当前缓存中没有发现可作为内容指纹的 MD5、SHA-1 或其他哈希字段。

### 2.2 按需目录缓存

本地 IndexedDB 不是完整网盘目录树，而是按需保存客户端访问过的目录。受控实验如下：

1. 夸克网盘中已有 `E01.mkv` 至 `E06.mkv` 六个文件；
2. 桌面客户端浏览对应目录后，本地缓存出现六个文件的丰富元数据；
3. 随后从网页端向其子目录上传 `pumpkin_book.pdf`；
4. 桌面客户端停留在父目录时，本地所有缓存均没有该 PDF；
5. 进入目标目录后，PDF 立即出现在 IndexedDB 中。

这说明客户端不会递归维护全盘元数据，也不能依靠父目录页面获知其他客户端对子目录产生的变化。IndexedDB 可以作为已访问目录缓存或变化提示，但不能直接满足 `Adapter.LoadSnapshot` 的完整性约束。

### 2.3 重复记录

同一文件可能在 IndexedDB 中重复出现。实测中的六个视频经过多次剪切操作后，各自出现多份历史记录。这符合 LevelDB 追加状态和延迟压缩的行为，不能把原始出现次数解释成网盘中的文件副本数。正式实现不能依赖扫描二进制字符串并按名称去重。

### 2.4 远端只读目录枚举

网页端使用 `GET https://drive-pc.quark.cn/1/clouddrive/file/sort` 分页读取某个目录的直接子项。小范围实测确认：

- `pdir_fid` 选择父目录，`_page` 和 `_size` 控制页码和页大小；
- 根目录和多层子目录都可以使用同一接口递归读取；
- 返回节点包含远端文件 ID、父目录 ID、名称、文件或目录标记、大小、分类、格式以及创建和修改时间；
- 脱敏结构检查确认响应顶层使用数值 `status=200`、数值 `code=0` 和 `data.list`；节点 ID、父 ID 和名称为字符串，`dir` 为布尔值，`file_type`、大小、分类及时间为数值；
- 当前目录节点为 `dir=true`、`file_type=0`，文件节点为 `dir=false`、`file_type=1`，创建和修改时间为 Unix 毫秒；
- `_fetch_total=1` 没有稳定返回可依赖的总数，扫描器应以“返回条数少于页大小”作为当前目录分页结束条件；
- 在六个视频文件的目录上将页大小设为 2，得到 `2 + 2 + 2 + 0` 条记录，文件 ID 无遗漏、无重复；
- 对当前测试账号执行一次有界全树扫描，共读取根目录及 5 个远端目录，得到 7 个文件；网页上传的 `pumpkin_book.pdf` 位于 `/工作/pumpkin_book.pdf`，与用户可见目录一致。

该接口是网页端内部接口，不应假定 URL、字段和分页规则长期稳定。正式扫描器必须严格解析响应、检测重复页和异常空洞，并把协议变化作为本次同步失败处理，不能发布可疑 generation。

### 2.5 认证边界

目录请求在页面运行时只设置 `credentials: include` 即可成功，请求中没有额外的 `Authorization` 或自定义签名头。同一请求改为不携带浏览器凭据后返回 HTTP 401 和“需要登录”，说明当前目录访问依赖浏览器 Cookie，而不是页面内另一个临时业务令牌。

登录态由多层 Cookie 组成，包括会话、短期和长期 Cookie，其中一部分为 HttpOnly。正常重载网盘页面时，网页会调用 `GET /1/clouddrive/auth/pc/flush`，并轮换、延长短期登录 Cookie；这证明正常会话存在浏览器侧续期，但尚不能替代真正的过期恢复测试。

夸克桌面客户端还提供了仅监听回环地址的本机桥接。网页端当前版本会依次探测 9125 至 9130，当前客户端实际监听其中一个端口。实测确认：

- 本机进程可以读取客户端版本和是否已经登录；
- 官方网页来源被允许通过 CORS 访问本机桥接；
- 桥接声明了由客户端长期登录态生成短期网页登录凭据的能力；
- 客户端运行时会独占锁定自身 Cookie 数据库，直接复制或解析 Cookie 文件既不稳定也没有必要。

第一版把已安装、正在运行且已经登录的夸克桌面客户端作为 Provider 的使用前提和唯一认证入口：

1. 探测固定的小范围回环端口，严格校验客户端信息响应和版本；
2. 确认客户端已经登录，否则只提示用户打开客户端并登录；
3. 通过客户端现有桥接发起网页登录请求，由用户在夸克客户端确认后，在内存中换取一次扫描所需的短期网页凭据；
4. 在独立的内存 Cookie jar 中完成只读目录扫描，扫描结束立即丢弃；
5. 不读取客户端 Cookie 数据库，不把任何令牌或 Cookie 放入命令行、环境变量、配置文件、日志或 Provider 数据库；
6. 收到 401 时关闭当前会话，保留 staging 进度和上一代已发布快照，再通过客户端重新授权并在同一次刷新命令中从原检查点续跑；客户端退出或重新授权失败时结束命令，staging 仍可供下次恢复。

该实现与任何夸克 Skill、开放平台 CLI 及其 OAuth 授权完全独立，不读取其安装目录、配置、缓存或登录态，也不把它作为回退路径。PanFind 的夸克 Provider 只使用本节描述的桌面客户端本机桥接与一次扫描专用的内存会话。

上述链路已经完成一次不落盘、不输出凭据的端到端验证：在夸克客户端保持登录的前提下，用户确认网页登录请求后，独立 HTTP 客户端成功在内存 Cookie jar 中建立会话，并以 HTTP 200、业务码 0 读取根目录；本次实测返回 `工作`、`临时`、`视频资源` 和 `来自：分享` 四个根目录项。会话共接收 6 个 Cookie，验证结束后已立即清空内存 Cookie jar。整个过程没有读取或复制客户端 Cookie 数据库，也没有把一次性凭据、Cookie 或账号信息写入磁盘或输出到日志。

代码中的认证组件保持同样边界：发现层保留桥接版本、客户端版本和登录状态，并把客户端提供的当前账号标识立即转换为单向 SHA-256 摘要，Provider 只使用摘要隔离账号，不保存或输出原始标识；授权分成“发起客户端确认”和“等待确认并建立会话”两段，便于调用层在两段之间明确提示用户；请求 ID、短令牌和服务票据只存在于内存，错误信息不包含带票据的 URL；会话使用独立 Cookie jar，关闭后会断开 jar 并阻止遗留 HTTP client 继续请求。目录接口收到 HTTP 401 时返回独立的认证过期错误，不把响应正文带入错误信息。

因此，桌面客户端认证方案具有实现可行性。客户端未安装、未运行或未登录时，第一版只返回明确的前置条件提示，不启动独立浏览器登录。浏览器回退可以在未来出现真实用户需求后另行设计，但不进入当前代码路径和测试范围。当前仍需验证真正授权过期后的识别与恢复行为，不能把一次成功登录等同于已经覆盖全部生命周期边界。

当前没有在夸克官方公开页面中找到面向普通网盘文件树的 OAuth 或目录 API 文档。这个观察不等于官方接口永久不存在；如果未来出现适合桌面工具的正式授权和目录 API，应优先替换网页内部接口和客户端桥接。

## 3. 非实时快照的需求依据

非实时不等于没有搜索价值。用户对近期主动新增、删除或移动的文件记忆最强，通常不依赖 Agent 搜索；用户真正需要寻找的往往是多年积累、名称和位置已经遗忘的历史文件，而这部分文件在最近几天发生变化的概率最低。

旧快照要实质性妨碍一次历史搜索，需要同时满足：历史文件恰好在快照后被移动，用户随即忘记这次主动操作，又在下一次刷新前要求 Agent 按旧线索寻找。这个低概率交集不值得成为持续全盘扫描和追求秒级一致性的默认理由。

因此，夸克 Provider 优先保证：

1. 快照覆盖完整目录树；
2. 快照内部一致，失败时不发布半棵树；
3. 查询只访问本地持久化数据；
4. 明确展示快照生成时间和年龄；
5. 由用户或计划任务按需执行下一次全量刷新。

完整需求论证见 [产品愿景与使用场景](产品愿景与使用场景.md#31-搜索需求与快照新鲜度的时间互补)。

## 4. 目标数据流

```text
已登录并运行中的夸克桌面客户端
        ↓  本机桥接换取内存短期凭据
纯内存短期认证会话
        ↓
夸克只读远端目录接口
        ↓
递归分页扫描器
        ↓
PanFind 持久化元数据数据库
        ↓
Quark Provider Adapter
        ↓
不可变 POSIX Snapshot
        ↓
AI Agent / CLI / scripts
```

远端是最终权威来源；PanFind 自己的数据库是最近一次成功扫描的持久化镜像；客户端 IndexedDB 只作为可选变化线索，不作为完整性依据。

这套可写数据库和扫描生命周期完全属于夸克 Provider。百度 Provider 仍然只读官方客户端的 `filecache.db`，不经过夸克的 staging、远端 ID 映射或发布流程。两种实现只在 `provider.Adapter` 输出完整 `namespace.Snapshot` 时汇合；公共 POSIX 命名空间不感知数据来自本地数据库还是远端扫描。

## 5. 首次初始化和全量刷新

首次同步从根目录开始，以广度优先或深度优先方式递归处理所有目录：

1. 分页读取一个目录的全部直接子项；
2. 将新发现的目录加入持久化扫描队列；
3. 将文件和目录写入 staging generation；
4. 保存分页和目录进度，允许进程退出后继续；
5. 对瞬时请求失败执行有界退避重试，并根据真实大盘验证结果决定是否需要固定基础限速；
6. 只有扫描队列清空且所有分页成功时，才原子发布新 generation；
7. 扫描失败或取消时，继续提供上一代完整快照。

全量刷新不应在每次查询或程序启动时隐式发生。它是用户明确触发或计划任务触发的维护动作，扫描期间查询继续使用旧快照。

## 6. 非实时一致性模型

没有远端 change feed 时，其他客户端产生的变化无法被及时发现。第一版明确采用非实时模型：

- 普通查询直接使用最近一次成功的完整快照；
- 用户需要时手动执行全量刷新；
- 可选地按日或按周计划全量刷新；
- 状态输出展示最近成功同步时间、可恢复扫描的精确目录计数和最近错误；
- 任务明确涉及“刚才”“今天”“最新上传”等近期变化时，Agent 可以建议先刷新；
- 不因快照较旧而阻塞普通历史搜索。

本地 IndexedDB 后续可以用于发现本机刚访问或操作过的目录，但它只能把目录标记为可能变化，不能直接证明完整的新增、移动或删除。任何局部刷新都必须保持快照完整性语义，不能把部分缓存直接合并后冒充全盘最新状态。

## 7. POSIX 字段映射

夸克远端文件 ID 是字符串，而当前 `namespace.NodeKey.ID` 是 `int64`。Provider 自己的数据库应维护远端 ID 到稳定内部 `int64` 的唯一映射，不需要扩大核心命名空间类型。

初始能力预期为：

```text
size=true
modified_at=true
created_at=true
added_at=false
hash=false
stable_id=true
incremental_hint=false
```

文件和目录的远端 ID 稳定性已经过真实操作验证。测试文件先在原目录内重命名，再跨目录移动；测试空目录也执行了相同的重命名和跨目录移动。四次操作中目标节点的远端 ID 均保持不变，重命名时父目录 ID 不变，移动时父目录 ID 按预期变化，旧路径同时从远端枚举结果中消失。因此第一版可以声明 `stable_id=true`，并使用远端 ID 维护跨 generation 的内部节点身份。缺失哈希时仍保持 `nil`，不能用稳定 ID 或其他字段冒充内容指纹。

## 8. 建议的持久化状态

Provider 自有数据库至少需要表达：

- `nodes`：当前已发布 generation 的文件和目录；
- `remote_ids`：远端字符串 ID 与内部 `int64` ID 的稳定映射；
- `sync_runs`：每次扫描的状态、起止时间和错误；
- `crawl_queue`：待扫描目录、分页位置和重试状态；
- `staging_nodes`：尚未发布的新 generation；
- `dirty_dirs`：来自本地缓存的可选变化提示。

具体表结构应在远端列表字段和分页语义验证完成后确定，不应提前绑定未经验证的客户端内部字段。

当前已经落地第一段最小持久化基础：

- `remote_ids` 按账号保存远端字符串 ID 到内部正整数 ID 的稳定映射；
- `sync_runs` 和 `nodes` 保存扫描中的 staging generation；
- `sync_runs` 同时保存扫描开始、最近尝试、最近进展、成功完成时间和有界长度的最近错误；
- `crawl_queue` 按发现顺序保存待扫描目录、远端目录 ID 和下一页页码；
- `published_generations` 只指向已经通过完整 POSIX 树校验的 generation；
- 一个远端响应页的节点写入、子目录入队和页码推进在同一事务中完成，允许进程退出后从未提交页继续；
- 只有队列存在且所有目录均已完成分页，generation 才有资格进入完整 POSIX 树校验；
- 发布失败或目录树残缺时不移动 published 指针，查询继续读取上一代完整快照。

扫描器只依赖夸克包内的强类型只读目录客户端，不感知 Cookie、桌面桥接或 HTTP JSON。它会拒绝超过请求页大小的响应、空远端 ID、父目录不一致和页内重复 ID；返回条数等于页大小时继续下一页，少于页大小时才完成当前目录。远端请求失败后，下一次运行从数据库中的原检查点继续。

重试策略作为目录客户端装饰层位于扫描器之外，不改变分页和检查点语义。调用方上下文仍有效时，网络超时、临时网络错误、HTTP 408、425、429 和 5xx 被归类为瞬时错误；单页最多尝试四次，默认退避为 250 毫秒、500 毫秒和 1 秒。服务端 `Retry-After` 大于本地退避时优先采用；若要求等待超过 30 秒，本次命令直接失败，不能提前重试违背服务端要求。HTTP 401 不进入该策略，而是交给桌面客户端重新授权流程；普通 4xx、响应协议错误和用户取消立即失败。所有失败都发生在当前页事务提交之前，因此重试不会重复推进检查点。

只读 HTTP 客户端和响应解码器已按照真实脱敏结构实现。仓库中的 fixture 只包含合成 ID、名称、大小和时间，不包含测试账号的真实响应值。解码器允许增加无关字段，但会拒绝核心状态、业务码、列表、ID、父 ID、名称、目录标记、类型、大小或时间的缺失及类型变化，也会拒绝 `dir` 与 `file_type` 语义冲突和尾随 JSON。

刷新编排现在把桌面客户端发现、用户确认、纯内存会话、目录客户端、检查点恢复、扫描发布和会话关闭连接为一条路径。认证成功后才创建 staging generation；同一账号已有未完成 generation 时直接恢复，HTTP 401 不移动当前页检查点，而是先关闭过期会话、记录错误，再请求客户端确认一个新会话并继续同一 generation。每个替换会话都必须属于最初账号；账号发生变化时明确失败，不能把两棵树混入同一个 generation。只要会话提交过分页进展，无进展计数就清零；连续三个会话都在没有提交任何分页的情况下过期时终止本次命令，避免无限弹出授权确认。其他扫描失败不会移动检查点或已发布指针；成功或失败都会关闭本次会话。

扫描开始、最近尝试和每个已提交分页的进展时间均持久化；失败原因写入 staging run，下一次真正提交远端分页时清除，完整发布时记录完成时间。即使取消导致原调用上下文失效，错误记录也使用短时、有界的清理上下文落盘。单个进程内的瞬时请求退避已经实现；跨进程重试状态、固定基础限速和旧 generation 清理仍属于后续实现。网页内部接口没有公开的稳定响应定义；未来协议变化应明确导致当前同步失败，不能静默发布可疑 generation，也不能把开放平台的另一套协议硬套进来。

`status quark` 的刷新状态为 `empty`、`ready`、`staging` 或 `failed`。对 staging run，它输出已发现、已完成、待处理的目录数以及已暂存节点数；目录总数会在递归扫描中继续增长，因此不输出虚假的完成百分比。认证会话建立之前的失败没有可靠的账号作用域，不创建 run；认证成功后发生的目录客户端或扫描失败可以持久化并在下一次刷新中恢复。

## 9. 下一步只读验证

正式实现前的小范围技术验证状态如下：

1. **已验证**：可以分页读取根目录；
2. **已验证**：可以递归读取多层子目录；
3. **已验证**：受控多页目录无遗漏、无重复，总数不能作为结束条件；
4. **已验证**：文件和目录在重命名、跨目录移动后远端 ID 均保持稳定，移动时父目录 ID 正确变化；
5. **部分验证**：已确认桌面客户端桥接、用户确认、独立内存会话建立和根目录读取；代码测试已验证 401 后关闭旧会话、再次授权并从原页续跑，连续无进展保护和账号切换拒绝也已覆盖；真实远端长扫描中的自然授权过期仍待验证；
6. **部分验证**：代码测试已覆盖网络超时、HTTP 408/425/429/5xx、`Retry-After`、指数退避、次数与等待上限、取消和永久错误不重试；真实远端限流阈值与基础请求间隔仍待大盘扫描验证；
7. **待验证**：是否存在可选的 cursor 或 change feed；
8. **部分验证**：刷新编排已通过真实桌面客户端完成一次全树扫描并发布正式本地快照，共得到 5 个目录和 7 个文件；强类型扫描器和编排测试已确认认证过期时保留原页、关闭旧会话，在同一次刷新命令中重新认证后从该页继续直至发布，真实 HTTP 请求中途过期仍待受控验证。

`internal/quark` 已完成稳定 ID、staging、原子发布和桌面认证刷新编排。真实集成测试默认跳过，显式启用时只读扫描远端元数据，使用测试临时数据库并在结束后删除。第一版只承诺可重复生成完整快照，不承诺实时同步。

应用层现已提供正式入口：`panfind refresh quark` 更新 PanFind 私有元数据数据库；`panfind quark:/ ...` 和 `capabilities quark` 只读取本地状态，`accounts quark` 还会发现只有可恢复 staging 的账号，`status quark` 同时读取最近一次成功快照和 staging 进度。查询路径不会隐式触发认证或远端刷新。

## 10. 非目标

第一版夸克 Provider 不做：

- 秒级跨设备同步；
- 上传、删除、移动或重命名；
- 用客户端零散缓存冒充完整目录树；
- 为获取哈希而下载全部文件；
- 在每次查询时访问远端；
- 客户端不可用时启动独立浏览器登录；
- 依赖夸克 Skill、开放平台 CLI 或其授权数据；
- 第三家网盘或通用插件系统。
